# Критерии ревью календаря звонков

Этот файл передаётся независимому ревьюеру в `.github/workflows/opencode-review.yml`. Ревьюер читает спецификацию из issue #6, тикеты #7 и #8, комментарий согласования в issue #5 и diff PR.

## Бронирование и свободные слоты

- Занятый слот не должен оставаться доступным для повторной записи — ни при бронировании с темой, ни без неё.
- Пересечение бронирований по времени по-прежнему отклоняется, слот при отказе остаётся свободным.
- Порядок встреч по времени и фильтрация завершившихся встреч не меняются.
- Хранение остаётся in-memory; данные сбрасываются при перезапуске, как зафиксировано в ADR-0002.

## Тема разговора

- Тема — необязательный свободный текст гостя до 200 символов, отдельный от описания типа встречи.
- Тема сохраняется вместе с бронированием и возвращается в ответе API и в списке предстоящих встреч.
- Пустая тема и тема из одних пробелов трактуются как отсутствие: бронирование создаётся, лишнего текста в списке нет.
- Тема длиннее 200 символов отклоняется до создания бронирования, слот остаётся свободным.
- Владелец видит тему в той же строке списка `/admin`, у нужной встречи. Встречи без темы не получают заглушку или `undefined`.
- Подтверждение записи для гостя, отдельная карточка встречи и показ описания типа встречи в списке не меняются.

## Формат замечания

Каждое замечание обязано содержать:

1. файл и строку (или точное место в diff);
2. условие, при котором возникает ошибка;
3. последствие для гостя или владельца.

Если подтверждённых дефектов нет, ревьюер прямо сообщает об этом и не выдумывает замечания. Форматирование проверяет линтер, повторять его вывод в ревью не нужно.

## Вне ревью

Выпуск приложения и откат опубликованной версии. Решение о мерже принимает человек после успешных проверок.
