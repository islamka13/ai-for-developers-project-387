# Хранение данных в памяти процесса

Типы встреч и бронирования храним в памяти процесса (in-memory), без базы данных. Перезапуск приложения сбрасывает данные — это осознанное ограничение, зафиксированное в README.md. Причины: курс прямо допускает такой вариант и не включает сохранение после перезапуска в приёмку; не нужны драйвер, схема и миграции; проще Docker-образ и локальный запуск. Рассматривали SQLite: даёт персистентность, но в Docker-контейнере без volume файл всё равно эфемерен, а кода заметно больше. Если позже понадобится персистентность, переход возможен: хранилище изолируем за интерфейсом репозитория.
